## Лабораторная № 6 — управление полиграфическими изданиями

Условие: [TASK.md](TASK.md). Исходники и сценарий сборки находятся в `lab6/`.
Требуется **JDK 17 или новее**. Maven, сетевой доступ при сборке и внешние
библиотеки не нужны. Команды из корня репозитория:

```bash
./lab6/build.sh build  # компиляция
./lab6/build.sh test   # компиляция и регрессионные проверки (по умолчанию)
./lab6/build.sh run    # демонстрация полного процесса для трёх типов изданий
```

Если Java не добавлена в PATH, задайте `JAVA_HOME`, например:

```bash
JAVA_HOME=/path/to/jdk ./lab6/build.sh test
```

Результаты сборки размещаются в игнорируемом каталоге `lab6/build/`.
Ошибки компиляции, предупреждения и проваленные проверки завершают сборку
с ненулевым кодом. Тесты используют собственные явные проверки, включать `-ea`
не требуется.

### Архитектура и соответствие условию

- `PublicationProcess` — интерфейс всех девяти действий: оформить договор,
  открыть, редактировать, верстать, отправить на печать, отказаться, оплатить,
  возобновить, закрыть издание.
- `Publication` — абстрактная реализация общих правил и инкапсулированного
  состояния. Общие операции `final`: наследники не могут обойти проверки.
- `PublicationState` — состояния процесса. Состояние и реквизиты доступны
  для чтения, изменяются только через операции процесса.
- `Book` — автор, изменение автора, добавление и просмотр глав.
- `Magazine` — положительный номер выпуска, его изменение, добавление
  и просмотр статей.
- `StudyGuide` — учебный предмет, его изменение, добавление и просмотр заданий.
- `Main` — исполняемый пример полиморфного управления через интерфейс.
- `PublicationTest` — проверки модели без внешних зависимостей.

Ориентиры из `origin/lab4` и `origin/lab5`: Java 17, пакеты `by.*`, отдельная
предметная модель, абстрактный базовый класс, проверка аргументов и защищённые
коллекции. Общая логика сосредоточена в модели: отдельный сервис, лишь повторяющий
её методы, не нужен. В отличие от денежных значений `double` из лабораторной 4,
расчёты ведутся через `BigDecimal`. Фабрики и логирование не добавлены:
условие их не требует, создание трёх типов изданий несложно.

### Принятые правила процесса

Условие перечисляет действия, но не определяет переходы, расчёты и смысл
возобновления. В реализации приняты следующие правила:

| Действие | Допустимые исходные состояния | Результат |
| --- | --- | --- |
| Оформить договор | NEW | CONTRACTED, сохранение заказчика и стоимости |
| Открыть | CONTRACTED | OPEN |
| Редактировать | OPEN, EDITED, LAID_OUT | EDITED, замена текста, сброс вёрстки |
| Верстать | EDITED, LAID_OUT | LAID_OUT, положительное число страниц |
| Отправить на печать | LAID_OUT при полной оплате | PRINTED |
| Оплатить | CONTRACTED, OPEN, EDITED, LAID_OUT | Частичная или полная оплата без смены состояния |
| Отказаться | CONTRACTED, OPEN, EDITED, LAID_OUT | REFUSED |
| Закрыть | CONTRACTED, OPEN, EDITED, LAID_OUT, PRINTED | CLOSED |
| Возобновить | REFUSED, CLOSED | Восстановление состояния перед отказом/закрытием |

Цена и каждый платёж положительны, допускают максимум два значащих десятичных
знака после запятой; переплата запрещена. Повторное оформление договора и
повторная печать запрещены. Отказ и закрытие сохраняют текст, специальные данные,
вёрстку и платежи; после возобновления оплачивать заново не нужно.

Специализированные методы изменяют данные только в OPEN, EDITED, LAID_OUT.
Изменение после вёрстки переводит издание в EDITED и сбрасывает число страниц;
перед печатью нужна новая вёрстка. Главы, статьи и задания — дополнительные
структурные данные; общий текст отдельно задаётся через `edit`.
Списки возвращаются неизменяемыми снимками. Пустые строки и некорректные числа
отклоняются через `IllegalArgumentException`, нарушения порядка действий —
через `IllegalStateException`, без частичного изменения данных.

Данные хранятся в памяти в рамках одного запуска. Графический интерфейс,
сохранение на диск, возвраты платежей и физическая отправка в типографию
не входят в условие; печать моделируется переходом состояния.

### Проверка

`./lab6/build.sh test` проверяет все девять действий в каждом из восьми состояний
для каждого типа издания, полный процесс, восстановление всех допустимых
состояний, точность и границы платежей, сброс вёрстки, валидацию аргументов,
специализированные изменения и неизменяемость возвращаемых коллекций.
`./lab6/build.sh run` выполняет процесс для книги, журнала и учебного пособия;
ожидаемый результат — три строки с состоянием `PRINTED` и оплатой `100.00`.
