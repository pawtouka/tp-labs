# Лабораторная № 7: функциональные интерфейсы и лямбда-выражения

Условие: [TASK.md](../TASK.md). Требуется JDK 17+, Bash; внешних зависимостей нет.
Команды из корня репозитория:

```bash
./lab7/build.sh build
./lab7/build.sh test  # также действие по умолчанию
./lab7/build.sh run
```

Если JDK отсутствует в PATH, перед командой укажите `JAVA_HOME=/path/to/jdk`.
Сборка использует `--release 17 -encoding UTF-8 -Xlint:all -Werror`.
Результаты находятся в игнорируемом `lab7/build/`. Тесты не требуют `-ea`.
`run` выводит результаты всех пяти операций для обоих способов.

## Соответствие условию

| Задание | Собственные интерфейсы (`CustomTasks`) | Интерфейсы JDK (`StandardTasks`) |
| --- | --- | --- |
| № 1: сложение | `TaskFunction<Integer, TaskFunction<Integer, Integer>>` | `Function<Integer, IntUnaryOperator>` |
| № 1: проверка regex | `TaskFunction<String, TaskFunction<String, Boolean>>` | `Function<String, Predicate<String>>` |
| № 1: разбиение regex | `TaskFunction<String, TaskFunction<String, String[]>>` | `Function<String, Function<String, String[]>>` |
| № 13: сортировка | `TaskFunction<int[], int[]>`, лямбда `IntOrder` | `Function<int[], int[]>`, лямбда `Comparator<Integer>` |
| № 25: панграмма | `TaskFunction<String, Boolean>` | `Predicate<String>` |

`TaskFunction` и `IntOrder` помечены `@FunctionalInterface` и объявлены нами.
Вариант JDK использует существующие интерфейсы `java.util.function` и `java.util`.
Все функции создаются лямбда-выражениями. Методы № 1 возвращают каррированные
функции: сложение принимает сначала левое число, затем правое; операции regex —
сначала регулярное выражение, затем строку. Частично применённые функции можно
использовать многократно; regex компилируется один раз при первом применении.

```java
var addTen = CustomTasks.addition().apply(10);
int fifteen = addTen.apply(5);
var isWord = StandardTasks.matches().apply("[A-Za-z]+");
boolean valid = isWord.test("Java");
```

## Архитектура и договорённости

Из `lab6` сохранены Java 17, пакеты `by.*`, отдельные main/test, автономный
сценарий сборки и явные проверки без библиотек. Из `origin/lab5` использованы
ориентиры разделения ответственности и работы с лямбдами/компараторами.
Классы двух способов независимы; общая семантика алфавита выделена в `Alphabet`,
чтобы не дублировать правила Unicode. `Main` демонстрирует оба способа.
Предыдущие лабораторные не изменены.

- Числа для сложения — `int`; переполнение вызывает `ArithmeticException`.
- Проверка regex охватывает **всю строку** (`Matcher.matches`). Разбиение
  соответствует `Pattern.split(text)` с limit=0: конечные пустые части удаляются,
  внутренние сохраняются. Некорректный regex вызывает `PatternSyntaxException`.
- Сортировка возвращает новый `int[]` по убыванию, сохраняя исходный массив,
  повторы и крайние значения `int`. Сравнение через `Integer.compare` исключает
  переполнение. Собственный интерфейс используется в сортировке вставками
  (O(n²)); стандартный — в `Arrays.sort` для упакованных чисел (O(n log n)).
  Это учебная реализация, собственный вариант рассчитан на небольшие массивы.
- Язык панграммы не указан в условии: алфавит задаётся явно. Готовы `ENGLISH`
  (a–z) и `RUSSIAN` (33 буквы, **ё обязательна**, отличается от е), можно создать
  свой `Alphabet`. Регистр игнорируется через `Character.toLowerCase` по Unicode
  code points; пробелы, цифры, пунктуация и посторонние буквы не мешают.
  Дубликаты букв алфавита игнорируются. Пустая строка не является панграммой.
  Пустой алфавит или небуквенные символы в нём вызывают `IllegalArgumentException`.
  Unicode-нормализация составных букв не выполняется: например, `ё` должна быть
  представлена одной буквой, а не `е` с отдельным диакритическим знаком.
- `null` в ссылочных входных данных вызывает `NullPointerException`.

## Проверки

`FunctionalTasksTest` проверяет оба способа: частичное применение и повторное
использование функций, переполнение суммы, полное соответствие regex, ошибки
шаблонов, пустые и соседние части при разбиении, пустые/одиночные массивы,
повторы и границы `int`, сохранение входного массива, 100 воспроизводимых
случайных массивов. Для панграмм проверяются оба регистра, оба языка, отсутствие
каждой отдельной буквы, `ё`, собственный алфавит и символы вне BMP, а также
некорректные аргументы. Проверки используют ожидаемые результаты, а не только
сравнение двух реализаций между собой.

Проверено на OpenJDK Temurin 17.0.21: `build` и демонстрация `run` завершились
успешно; `test` — `PASS: 619 checks`. Предупреждений компилятора нет.
